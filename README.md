# API Security Framework: Automated BOLA Detection

Automated testing for **Broken Object Level Authorization (BOLA)**, #1 in the OWASP API Security Top 10, using a Python two-user test engine, **Postman/Newman** collections and **OWASP ZAP**.

## Project description

BOLA happens when an API checks *who you are* but not *whether the object you asked for belongs to you*. This framework detects it automatically:

1. Logs in as several users and, for every endpoint and HTTP method, has user A request user B's objects.
2. Classifies each case as `VULNERABLE`, `SECURE` or `INCONCLUSIVE`, with severity (Critical / High / Medium) and a data-leak check.
3. Exports the same test matrix as a **Postman collection** (run headless with Newman in CI).
4. Drives an **OWASP ZAP** spider and active scan through its API for broader coverage.
5. Writes CSV / JSON / Markdown reports and a CI pass/fail gate.

The notebook ships with an intentionally flawed **demo API** (v1 has no ownership checks; v2 is a partial fix that forgot `DELETE`), so everything runs without external setup.

**Demo run result:** 80 test cases, 46 vulnerable. All four v1 endpoints fail, and `v2 DELETE order` is caught as a missed fix. The v2 GET/PUT/profile endpoints pass.

## Technologies used

Python 3.10+, Jupyter Notebook, Flask (demo API), requests, pandas, matplotlib, Postman collection v2.1 + Newman, OWASP ZAP (`python-owasp-zap-v2.4`).

## Dataset

No external dataset. Test data is generated by the built-in demo API (3 users, 5 orders, 3 profiles).
To test a real target instead, any of these deliberately vulnerable APIs work well:

- OWASP crAPI: https://github.com/OWASP/crAPI
- VAmPI: https://github.com/erev0s/VAmPI

## Setup and run

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. (Optional) Newman for running the Postman collection
npm install -g newman

# 3. (Optional) OWASP ZAP daemon for the ZAP cell
zap.sh -daemon -port 8080 -config api.key=changeme
export ZAP_API_KEY=changeme

# 4. Run the notebook
jupyter notebook YourName_APISecurityFramework.ipynb     # Run All
```

Outputs are written to `./output/`: `bola_results.csv`, `bola_results.json`, `bola_report.md`, `bola_collection.postman.json`, `local.postman_environment.json` (plus `zap_alerts.csv` and `newman_report.json` when ZAP / Newman are available).

The ZAP and Newman cells skip gracefully if those tools are not installed.

## Testing your own API

Edit the **Configuration** cell: set `BASE_URL`, `USE_DEMO_API = False`, `RESET_URL = None` (unless you have a reset endpoint), and fill in `USERS`, `RESOURCES` (object IDs each user owns) and `ENDPOINTS`.

## Key information

- Only test APIs you own or have written permission to test.
- `PUT`/`DELETE` tests modify data. Use disposable test data, or set `ALLOW_DESTRUCTIVE = False`.
- ZAP cannot know object ownership, so it complements the two-user engine rather than replacing it.
- Fix: enforce an ownership check in **every** handler (centralised via middleware or scoped queries), then re-run the suite in CI.
